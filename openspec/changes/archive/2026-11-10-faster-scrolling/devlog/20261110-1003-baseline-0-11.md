# Baseline on Neovim 0.11.0

<!-- Section: 1 · Tasks: 1.1 · Base: 014df00 -->

Before §1 started, the user asked for no benchmark in `gates.ps1` ("annoying"), so the proposal, design
(decision 7) and tasks were changed to a throwaway measurement (commit `014df00`), and the
`config-health` "scroll benchmark" requirement was dropped.

The measurement lives outside the repo: `$env:TEMP\opencode\measure.ps1` runs
`$env:TEMP\opencode\tuibench.lua` in a `conhost.exe` Neovim (`-u init.lua`, `lines=40 columns=160`, 5 s
settle, 300 × `normal! j` + `doautocmd CursorMoved` + `redraw`), on a generated 6,006-line C# file
(`Big.cs`) and a 7,500-line Lua file (`big.lua`) in the same folder. Each setup first restores the
config's own values, captured at start. If `%TEMP%` gets cleaned, rebuild it from design decision 7.

Run 1:
```
cs   (defaults)          2.13 ms/step  hl=regex lsp=
cs   highlighting off    0.72 ms/step  hl=regex lsp=
cs   set norelativenumber  1.82 ms/step  hl=regex lsp=
cs   set nocursorline    0.91 ms/step  hl=regex lsp=
cs   NoMatchParen        1.42 ms/step  hl=regex lsp=
lua  (defaults)          0.47 ms/step  hl=ts    lsp=lua_ls
lua  highlighting off    0.32 ms/step  hl=regex lsp=lua_ls
lua  set norelativenumber  0.31 ms/step  hl=ts    lsp=lua_ls
lua  set nocursorline    0.43 ms/step  hl=ts    lsp=lua_ls
lua  NoMatchParen        0.19 ms/step  hl=ts    lsp=lua_ls
```
Run 2:
```
cs   (defaults)          1.46 ms/step  hl=regex lsp=
cs   highlighting off    0.44 ms/step  hl=regex lsp=
cs   set norelativenumber  1.41 ms/step  hl=regex lsp=
cs   set nocursorline    0.68 ms/step  hl=regex lsp=
cs   NoMatchParen        1.35 ms/step  hl=regex lsp=
lua  (defaults)          0.54 ms/step  hl=ts    lsp=lua_ls
lua  highlighting off    0.44 ms/step  hl=regex lsp=lua_ls
lua  set norelativenumber  0.43 ms/step  hl=ts    lsp=lua_ls
lua  set nocursorline    0.43 ms/step  hl=ts    lsp=lua_ls
lua  NoMatchParen        0.28 ms/step  hl=ts    lsp=lua_ls
```

Reading it: "highlighting off" lines say `hl=regex` only because of a labelling bug (`syntax off` keeps
`vim.bo.syntax`); highlighting was really off. The label is fixed in the script for later runs. Runs are
noisy (±30 %), but the shape is stable: in C#, regex highlighting is about ⅔ of the cost, and
`cursorline` multiplies it. In Lua (tree-sitter), everything is under 0.6 ms. Roslyn didn't attach to
`Big.cs`, which has no `.csproj` next to it, so semantic tokens are not in these numbers.
