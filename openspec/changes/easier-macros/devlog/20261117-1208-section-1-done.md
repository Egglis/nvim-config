Planning (previous turn, with the user): researched built-in macros (`Q`, `@@`, visual `Q`/`@`),
which-key's `registers` plugin, snacks' `registers` source, nvim-recorder and NeoComposer. The user chose
**defaults + small glue** and all three pieces: lualine REC indicator, register popup on `@`, macro picker
+ editor. `<leader>fm` and `<C-e>` (edit) were my picks, stated in the proposal; the user said "go ahead".

Done: `lua/plugins/lualine.lua` has a `recording` component after `mode` in `lualine_a` (`REC @<reg>`,
fg = `Normal` bg, bg = `DiagnosticError` fg, bold) and a `lualine_recording` augroup that refreshes the
statusline on `RecordingEnter` and (scheduled) `RecordingLeave`. AGENTS.md has a new `### Macros` section
(built-in keys table + indicator), placed before `## Plugins`.

Verified in a real headless Neovim driven over RPC (`nvim --headless --listen sock`, keys via
`nvim --server sock --remote-send`, state via `--remote-expr "luaeval('…')"`; statusline read with
`nvim_eval_statusline(vim.wo.statusline …)`):
- 3× `qa` → 50 ms later statusline ` NORMAL  REC @a  [No Name] …`; `q` → 50 ms later no `REC` (lualine's
  own timer is 1000 ms, so it's the autocmd refresh).
- `qq A ; <Esc> j q 3Q` on `a..e` → `a;,b;,c;,d;,e`; `jVjjQ` → `a,b;,c;,d;,e`; `jVj@q` → `a,b;,c;,d,e`.
- `./gates.sh gates` → `BUILD_EXIT:0` `FORMAT_EXIT:0` `VALIDATE_EXIT:0` `GATES_EXIT:0`.

Gotcha (pre-existing, not this change): sending a whole recording in **one** `--remote-send`
(`qqA;<Esc>jq`) records only `A` — nvim-cmp's insert-mode handling drops the rest of a same-batch
typeahead from the recording (confirmed: clearing the `___cmp___` augroup fixes it; same on the base
commit). Keys sent one at a time (as when typing) record fine. Headless tests must send keys one by one.
Worth asking about in the human check (fast typing / pasted keys while recording).
